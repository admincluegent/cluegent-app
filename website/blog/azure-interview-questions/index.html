Azure Interview Questions: Identity, Queues and Workload Recovery

How would you choose an Azure compute service?

Begin with the workload's runtime, deployment model, traffic pattern and operational needs. Compare supported options against those requirements rather than naming the service you used most recently. A continuously running application and an event-driven task can need different lifecycle and scaling behavior. State the expected load and what your team needs to control before recommending a platform.

What does managed identity help with?

It provides an identity for supported workloads to access resources without the application managing a traditional secret in the same way. Permissions still require an explicit access decision. Explain the identity, target resource and allowed operation. Do not equate receiving a token with permission to every resource. Review whether the workload's configured role grants more access than its actual task requires.

How should a queue consumer handle repeats?

Assume the relevant delivery contract may require duplicate handling and define a stable work identifier. Coordinate completion with the stored result and account for a crash before acknowledgment. A message disappearing from the queue does not by itself prove that the business result was saved. Explain invalid-message handling and safe recovery rather than endlessly retrying input that cannot succeed.

How do you discuss availability and recovery?

Name the user-facing operation and its tolerance for interruption or data loss. Redundancy, backup and recovery solve different aspects of that requirement. Explain which dependencies and identities must also work during recovery. A second application instance is not a full disaster-recovery plan if both depend on the same unavailable data path. Test restoring the intended service, not merely starting compute.

What should cost optimization preserve?

Preserve the required latency, capacity and recovery behavior while measuring actual usage. Identify unused capacity, inefficient work and storage lifecycle needs before changing the design. A cheaper component can increase operational work or violate response requirements. Explain the before-and-after workload and a controlled comparison rather than quoting a bill from an unrelated application.

Worked interview scenario

Original case: users upload documents and a queued worker extracts a summary. Give the upload a stable job ID and separate accepted, processing, failed and completed states. Configure the workload identity to access only the resources its role needs.

Now crash the worker after saving a summary but before acknowledging the message. Explain how a repeat sees the existing result instead of creating inconsistent copies. Add a permanently unreadable document and define an investigation path. For recovery, identify both the original file and the job state needed to resume work. A restored worker with no access to those records cannot complete the customer journey.

Practice exercise

Draw upload storage, job state and the queue consumer. Explain the role of each identity and one forbidden operation. Rehearse duplicate delivery and recovery from an unavailable dependency. Finish with a cost change whose success can be measured without compromising the job's latency requirement.

Frequently asked questions

Does managed identity grant every permission automatically?

No. The identity still needs access appropriate to the target resource and operation.

Is backup the same as high availability?

They address different needs. Define interruption and data-loss requirements, then design and test the corresponding mechanisms.
